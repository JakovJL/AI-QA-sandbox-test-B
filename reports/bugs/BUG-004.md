# BUG-004: Store API — `limit=-1` в `/store/products` вызывает HTTP 500 вместо валидационной ошибки

| Поле | Значение |
|------|----------|
| ID | BUG-004 |

| Severity | Low |
| Priority | P3 |
| Слой | API |
| Окружение | sandbox-session-cand-c26fa443df2a4d52ba4c0f61ea385fac.fly.dev, Medusa v2, 28.09.2026 |
| Воспроизводимость | всегда |
| Статус | Confirmed → **объединён с BUG-005** (28.09: фаззинг показал системный характер по всем листингам) |

## Предусловия

Валидный publishable key.

## Шаги воспроизведения

1. `GET /store/products?limit=-1` с заголовком `x-publishable-api-key`.

## Ожидаемый результат

400 (validation error) с указанием некорректного параметра `limit`, как это происходит
с другими некорректными входами в этой же системе (например, `quantity=0` в корзине даёт
структурированную 400 `invalid_data`). Основание: контракт обработки ошибок API v2;
согласованность с обработкой прочих негативных входов.

## Фактический результат

HTTP 500: `{"code":"unknown_error","type":"unknown_error","message":"An unknown error occurred."}`
— серверная ошибка вместо отклонения невалидного параметра. Для сравнения: `limit=0`
обрабатывается штатно (200, пустая страница).

## Артефакты

- `reports/artifacts/catalog-limit-negative.json`, `catalog-limit-0.json` (контраст)
- сводка: `reports/artifacts/stage2.1-catalog-*.json`
- воспроизведение: `npx tsx scripts/ts/api-contracts-catalog.ts`

## Примечания

- Не влияет на данные (read-only), но сигнализирует о дыре в валидации листинговых параметров:
  любые нестандартные значения пагинации могут уходить в необработанные исключения.
- Проверено только на `limit=-1`; диапазон иных отрицательных/нефитованных значений — в 2.5
  (Schemathesis), с лимитами по §13.5.
- **28.09 (этап 2.5):** Schemathesis подтвердил системный характер — отрицательные
  `limit`/`offset` дают 500 на всех листинговых эндпоинтах. Объединено с BUG-005;
  данный репорт остаётся как первичная точечная фиксация.
