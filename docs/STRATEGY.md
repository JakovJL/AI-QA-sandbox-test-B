# Стратегия: как мы ищем и подтверждаем дефекты (кратко)

> Полная программа — `docs/PLAN.md`. Этот файл — рабочая выжимка конвейера: контуры,
> поток находка→дефект, критерии бага. Ничего из здесь не описанного не отменяет план.

## Конвейер

```
база сравнения → исследование (контур А / API / NFR)
      → находка-кандидат (R-XXX, «нарушено»)
      → детерминированное подтверждение (контур Б) + артефакты
      → чекпойнт с пользователем → BUG-XXX + реестры
      → сводный отчёт прогона
```

## Два контура

| | Контур А — исследование | Контур Б — подтверждение |
|---|---|---|
| Инструменты | живой браузер / browser-инспекция | Playwright + headless chromium + TS-скрипты (`scripts/ts/`) |
| Роль | **обнаружение**: ходить как пользователь, замечать странности | **доказательство**: повторяемый сценарий + сырые артефакты (JSON/HAR/скриншот) |
| Слабость | «слова агента» — не доказательство | не придумывает, что проверять |
| Сеть | браузер пользователя (DoH) | пиннинг IP (`lib/target.ts`) / `--host-resolver-rules` — обход DNS-фильтра |

Правило: **находка рождается в А (или в API-зондировании), подтверждается только в Б.**

## Находка ≠ дефект (PLAN.md §2)

Кандидат становится BUG-XXX, когда сходятся три вещи:

1. **Ожидание с основанием** — запись в `registry/requirements.md` (док Medusa v2 / спека /
   согласованность Store ↔ Admin ↔ UI). Основание прямо влияет на severity; слабое основание —
   «наблюдение вне дефектов» (PLAN.md §13).
2. **Воспроизводимость** — детерминированный прогон в контуре Б (скрипт с зафиксированными шагами).
3. **Артефакт** — сырой ответ/скриншот в `reports/artifacts/` (вне git), пути — в багрепорте.

## Учёт

- Требования-по-наблюдению и допущения: `registry/requirements.md`, `registry/assumptions.md`
  (у каждого — основание и как проверим).
- Кейсы: `registry/test-cases.md` → статус и дефект(ы).
- Багрепорты: `reports/bugs/BUG-XXX.md` по шаблону `reports/templates/bug-report.md`;
  сводный отчёт — `reports/templates/run-report.md`.
- Чекпойнты: согласие на план этапа и согласие на подтверждённые дефекты до создания BUG-XXX.

## Ограничения выводов

См. `docs/PLAN.md` §13: посаженные баги vs кастомизация, согласованность ≠ доказательство,
