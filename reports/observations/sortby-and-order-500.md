# Наблюдение: сортировки витрины sortBy — URL меняется, порядок нет; API order=price_* → 500

**Дата:** 28.09.2026 · **Слой:** UI+API · **Статус:** наблюдение + усилитель BUG-005
**Области:** 1. Каталог и пагинация; 10. Контракты и ошибки

## Что наблюдается

1. На `/dk/store` селектор «Sort by» предлагает: Latest Arrivals, Price: Low → High,
   Price: High → Low. Выбор меняет URL (`?sortBy=price_asc` / `price_desc`), но порядок
   товаров **не меняется** — детерминировано контуром Б (`verify-ui-journeys.ts`, проверка D).
2. В момент проверки это ожидаемо «бесполезно»: у всех 4 товаров одинаковая цена
   `calculated_amount=10` (сверено через API с region_id) — сортировать нечего.
3. Однако параметры, которые витрина отправляет на бэкенд для сортировки по цене
   (`order=price_asc` / `price_desc`), вызывают **HTTP 500** на `/store/products`
   (артефакт: `reports/artifacts/`, прогоны 2.1; `order=nonsense` → 500 тоже).
   Корректные значения API — `order=created_at` (200).

## Почему не отдельный BUG-XXX

- Порядок на витрине сейчас неотличим от сортированного: цены равны → пользовательского
  ущерба нет; после наполнения каталога разными ценами поведение могло бы стать дефектом.
- Серверная часть (500 на `order=price_*`) — уже покрыто BUG-005 как класс «невалидные
  параметры пагинации/сортировки → 500 вместо 400». Дублировать не считаем правильным.

## Действие

- В реестре кейсов TC-012 помечено «pass/fail-контраст, наблюдения».
- Усилитель для BUG-005: в репорт добавлено, что класс невалидных `order`-значений ведёт
  себя так же (см. BUG-005, примечания).
- При появления товаров с разными ценами — переоткрыть как UI-дефект «сортировка не работает».
