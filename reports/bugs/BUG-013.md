# BUG-013: Сабмит адресной формы в чекауте не работает — переход на delivery не происходит

| Поле | Значение |
|------|----------|
| ID | BUG-013 |
| Область | 6. Чекаут / 11. UI-состояния |
| Severity | High |
| Priority | P1 |
| Слой | UI (сборка storefront) |
| Окружение | sandbox-session-cand-c26fa443df2a4d52ba4c0f61ea385fac.fly.dev, Next.js storefront (сборка после 28.09), контур Б (29.09.2026) |
| Воспроизводимость | всегда (5/5 десктоп + 3/3 мобайл прогонов; 4 способа сабмита) |
| Статус | Confirmed (контур Б, артефакты: сеть + координаты + скриншоты) |

## Предусловия

Гостевая корзина с 1 товаром; чекаут открыт на `?step=address`.

## Шаги воспроизведения

1. PDP (инлайн-варианты) → выбрать размер → Add to cart.
2. Корзина → «Go to checkout» → `?step=address`.
3. Заполнить все required-поля: first/last name, address_1, postal_code, city, country_code
   (Denmark), email (`qa-regress@test.local`), phone.
4. Нажать «Continue to delivery».

## Ожидаемый результат

Переход на шаг delivery (`?step=delivery`) с сохранённым адресом. Основание: пользовательский
сценарий чекаута; в сборке 28.09 тот же сабмит работал (этап 3: 5/6 прогонов чисто).

## Фактический результат

Ничего не происходит: URL остаётся `?step=address`, **ноль сетевых запросов**, ноль ошибок в DOM,
ошибок валидации нет (все required заполнены). Воспроизведено 4 способами:

1. programmatic `element.click()` — 0 запросов;
2. нативный клик Playwright (actionability OK, boundingBox 24×564 179×40, `disabled=false`) — 0 запросов;
3. Enter в поле email — 0 запросов;
4. `form.requestSubmit()` — 0 запросов.

В 8/8 серийных прогонов (`regress-ui-summary.json`) URL после сабмита не изменился
(мобайл-прогоны прерваны на ожидании поля — форма не отрисовалась в скролл-порте).

## Ожидаемо vs фактически (сеть)

Перехват `page.on("response")` на 15 c после клика: **пусто** — обработчик сабмита не
инициирует ни `POST /store/carts/{id}`, ни любого другого вызова. Гипотеза: в новой сборке
сломан/не привязан onSubmit-хендлер формы адреса (изменение сборки витрины после 28.09,
см. `reports/run-regression-2026-09-29.md`).

## Влияние

Блокер конверсии: гость не может пройти чекаут дальше шага address. Покупка через UI
невозможна (усиливает вердикт BUG-008 — механизм изменился: теперь блокировка раньше).
