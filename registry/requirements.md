# Реестр требований-по-наблюдению

> Требований нет, поэтому базовая линия строится из документации Medusa v2 и наблюдаемого поведения.
> Формат: ожидание + основание (док / наблюдение / согласованность) + статус подтверждения.
> Статусы: `подтв. нагрузкой` — проверено многократно; `предв.` — единичное наблюдение, перепроверить.
> Основание `док` — docs.medusajs.com/api (v2). Наполнено на аналитическом входе этапа 1 (28.09.2026).

| ID | Ожидание (как должно быть) | Основание | Статус |
|----|----------------------------|-----------|--------|
| R-001 | `GET /store/products` отдаёт список с корректным `count` и пагинацией `offset/limit` | док (v2 Store) | предв. — count=2 при 2 товарах; детально в этапе 2 |
| R-002 | `/us/*` и `/products/*` редиректят (307) на активный регион `/dk/*` | наблюдение | предв. |
| R-003 | Каталог-страница витрины — `/dk/store`, категории — `/dk/categories/{handle}` | наблюдение (200) | предв. |
| R-004 | Карточки `/dk/products/{handle}` отдают 200 для существующих и 404 для несуществующих хэндлов | наблюдение + согласованность | предв. |
| R-005 | `GET /store/customers/me` и `GET /store/orders` без аутентификации → 401 | док (v2 Store) | подтв. нагрузкой (карта) |
| R-006 | `/store/shipping-options` и `/store/payment-providers` без `cart_id` → 400 | док (v2 Store) | подтв. нагрузкой (карта) |
| R-007 | Ресурс настроек магазина в v2 — `GET /admin/stores` (множественное); `/admin/store` → 404 | док (v2 Admin) | подтв. нагрузкой (карта) |
| R-008 | Admin-списки (products, orders, regions, users, promotions, campaigns, api-keys, inventory-items, shipping-options) отдают 200 с валидным JWT | док (v2 Admin) + наблюдение | предв. |
| R-009 | Страница поиска `/dk/search?q=…` рендерит результаты для валидного `q`; в шапке витрины есть элемент поиска | ожидание от starter-витрины (пользовательский сценарий) | **нарушено:** 404 на любые `q` + **в шапке нет иконки/ссылки поиска** (контур А, 28.09) — кандидат №0, подтверждение в контуре Б |
| R-010 | Фильтр `/store/products?tag_id=` по существующему тегу возвращает только товар с этим тегом; по несуществующему — пустой список 200 | док (v2 Store) | предв. (наблюдение разведки) |
| R-011 | Валюта цен на витрине региона соответствует валюте региона (`eur` для Europe) | согласованность Store ↔ UI | **уточнено 28.09:** живой UI показывает `€` — валютный кандидат разведки (27.09, `$`) не воспроизводится; остаётся кандидатом масштаба (R-014) |
| R-012 | `/robots.txt` и `/sitemap.xml` существуют и синтаксически валидны | наблюдение (200) + конвенция SEO | предв. |
| R-013 | `count` в списковых ответах = общее число записей независимо от `limit` | док (v2 list response) | **нарушено в Store:** `/store/products?limit=N` → `count=N` (Admin — корректно: count=4 при limit=1); кандидат-дефект Store API |
| R-014 | Цены в минорных единицах: `calculated_amount=10 eur` = €0,10; витрина должна показывать сумму, соответствующую расчётной цене API | док (v2 prices) + согласованность API ↔ UI | **нарушено:** UI показывает €10,00 при API-цене €0,10 (×100); подтверждение скриншотами — контур Б |

## Снято с учёта (пересмотр ожиданий)

- «`GET /admin/store` → 404 это дефект» — **не требование**: в v2 путь `/admin/stores`; ожидание было от v1.
