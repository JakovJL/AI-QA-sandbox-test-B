## Наблюдения вне дефектов

- Текст валидации корзины «expected at least: '0'» при отклонении `quantity=0` — противоречит
  поведению (0 не принимается); косметика.
- `GET /admin/orders` (список) не включает email/currency в дефолтную проекцию — деталь их отдаёт.
- 307-редиректы при быстрой серии запросов (edge-слой) — перепроверить в NFR-этапе (A-005).
- Фаззинг: `valid_rates` во всех листингах > 0; except-класс один (ServerError) — глубже
  копать при повторных прогонах с новыми seed.
- OpenAPI-спека целью не отдаётся (`/openapi.json` перехвачен витриной) — фаззинг шёл по
  мини-спеке карты этапа 1; полное покрытие контрактов ограничено этим.

## Вердикт

Ядро коммерческого цикла (каталог → корзина → доставка → заказ) работает корректно и
предсказуемо обрабатывает большинство негативных входов — обработка ошибок корзины образцовая.
Системная слабость — **валидация параметров листингов и query-слоя**: два класса входов
(отрицательная пагинация, NUL) стабильно конвертируются в необработанные 500; плюс
нарушение контракта `count`. Дефекты локальны, на данные и на чекаут не влияют.

Главные риски дальше: UI-слой (поиск, чекаут в интерфейсе, мобильный вьюпорт) — Этап 3;
NFR-поведение под нагрузкой и заголовки безопасности — Этап 4.

Ограничения достоверности: sandbox общий (шум латентности), слепая зона capture платежа
(A-006), посаженные баги vs кастомизация (§13.1) — при трактовке учтено.
