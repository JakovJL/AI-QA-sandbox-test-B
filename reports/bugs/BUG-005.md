# BUG-005: Отрицательные `limit`/`offset` вызывают HTTP 500 на всех листинговых эндпоинтах Store API

| Поле | Значение |
|------|----------|
| ID | BUG-005 |
| Область | 10. Контракты и обработка ошибок API / 1. Каталог и пагинация |
| Severity | Medium |
| Priority | P2 |
| Слой | API |
| Окружение | sandbox-session-cand-c26fa443df2a4d52ba4c0f61ea385fac.fly.dev, Medusa v2, 28.09.2026 |
| Воспроизводимость | всегда |
| Статус | Confirmed (Schemathesis 4.28 + детерминированная репродукция) |

## Предусловия

Валидный publishable key.

## Шаги воспроизведения

1. `GET /store/products?limit=-12&offset=-20` → HTTP 500
2. То же для `/store/collections`, `/store/regions`, `/store/product-tags`, `/store/product-categories`.

## Ожидаемый результат

400 (validation error) с указанием некорректного параметра. Основание: контракт обработки
ошибок v2; согласованность (негативные входы корзины дают структурированные 400).

## Фактический результат

HTTP 500 `{"code":"unknown_error","type":"unknown_error","message":"An unknown error occurred."}`
на **каждом** листинговом эндпоинте при отрицательных `limit`/`offset`.

## Артефакты

- `reports/artifacts/fuzz-store-*-limit-12-offset-20.json` (6 эндпоинтов, 500-е)
- лог фаззинга: `reports/fuzzing/last-run.log`; JSON-отчёт: `reports/fuzzing/schemathesis-report/json-*.json`
- воспроизведение: `bash reports/fuzzing/run-fuzz.sh` (лимиты: ≤30 req/мин, GET-only, seed фиксируется в отчёте)

## Примечания

- Сужает BUG-004: проблема не в единичном `limit=-1`, а в системном отсутствии валидации
  пагинационных параметров во всех листингах (вероятно, отрицательные значения уходят в SQL).
- На данные не влияет (read-only), но 500-е — грубое нарушение контракта и шум для мониторинга.
- Смежное, не подтверждено отдельно: `cart_id` с NUL/юникодом → 500 на `/store/shipping-options`
  (см. `fuzz-store-shipping-options-cart-id-*.json`) — кандидат BUG-006, требует отдельного
  подтверждения (проверить, что корзина при этом не затрагивается — проверено: read-only).
- **28.09 (этап 3):** класс расширен — `order=price_asc|price_desc|nonsense` в
  `/store/products` тоже дают 500 (корректен `order=created_at`); витрина же отправляет
  именно `price_asc/price_desc` из селектора сортировки. Наблюдение:
  `reports/observations/sortby-and-order-500.md`.
