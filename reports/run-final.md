Программа из 5 этапов (API → UI → NFR), 3 контура (bash-hарнесс / живой браузер / headless chromium),
все дефекты — с детерминированным воспроизведением и сырыми артефактами.

| Класс | Дефекты |

## Как тестировали

Слои, от наружного внутрь:

1. **Карта поверхностей** (этап 1): read-only зондирование Store/Admin API (21 путь) и страниц витрины (16 маршрутов) — базовая линия без догадок. Скрипты: `scripts/api-map.sh`, `pages-map.sh`.
2. **API-контракт** (этап 2): пагинация/фильтры/сортировки/fields (13), негативные корзины — кривые variant/qty/чужие ID/ключи (12), полный чекаут-файнлайн с идемпотентностью (7), Store↔Admin дифференциал. Фаззинг Schemathesis по мини-спеке в лимитах (GET-only, ≤30 req/мин).
3. **UI как пользователь** (этап 3): живой браузер (контур А) — витрина/карточка/корзина/чекаут на десктопе и 390×844; headless chromium (контур Б) — детерминизация каждого сценария; DOM-замеры, сеть, консоль, скриншоты.
4. **UI-API сверки** — самый урожайный слой: пустой delivery при живом API, localhost-фетчи в клиентском бандле, мета-теги на 127.0.0.1.
5. **NFR** (этап 4): матрица security-заголовков на 4 поверхностях, флаги куки, SEO-эндпоинты, axe-core на 5 страницах, стабильность (30 замеров, p50/p95).
6. **Root cause** — спуск в network-логи, когда симптом был виден: захардкоженный `127.0.0.1:9001` объяснил три разных симптома (disabled варианты, пустой delivery, класс «localhost в прод-артефактах» с og:image).

## Как верифицировали

- **Правило находка ≠ баг:** кандидат становился BUG-XXX только с (а) ожиданием и основанием (док Medusa v2 / спека / согласованность), (б) детерминированным прогоном в контуре Б, (в) сырым артефактом. Одно наблюдение = candidate в реестре.
- **Сверка с эталоном:** каждый кандидат проверялся по документации Medusa v2; **4 кандидата отклонены** (конвенция major units, `/admin/stores` вместо v1-пути, ложный «200» зонда, валютный кандидат невоспроизводим) — все с разбором причин.
- **A/B-контроль изменчивых вещей:** count-пагинация и 307-аномалия проверялись повторными прогонами; интермиттентность BUG-007 измерена сериями (5+1+1 прогонов), а не «показалось».
- **Чекпойнты с заказчиком:** план этапа и переход кандидатов в дефекты — только после согласия (2 чекпойнта на этап).
- **Предохранители:** без реальной оплаты, без массовых мутаций, маркировка данных `@test.local`/`qa:true`, лимиты фаззинга, очистка по §13.5.

## Вердикт по sandbox

**Функционально: каталог и корзина работают, покупка через UI завершена быть не может.**
Воронка сломана на шаге Delivery (пустые способы + localhost-фетчи в клиенте), первый сабмит
адреса изредка выбивает на 404. API-слой здоровее UI: чекаут через API проходит полностью,
но контракт `count` нарушен и класс невалидных входов конвертируется в необработанные 500.
NFR — конфигурационная гигиена: ни одного security-заголовка, сломанные SEO-эндпоинты,
localhost в мета-тегах, систематические a11y-нарушения.

Sandbox явно подготовлен с намеренными дефектами (баннер `blocking-fault.js` «you found a
bug», следы ручных правок) — программа подтвердила этот профиль и локализовала причины.

## Рекомендации (по убыванию эффекта)

1. **Чекаут-воронка (BUG-008/007):** заменить localhost-URL в клиентской сборке на публичный
   домен; устранить гонку регион-кода при построении redirect-URL. Это вернёт монетизацию.
2. **Валидация входов (BUG-005/006):** централизованный валидатор пагинации/order/строковых
   параметров до слоя БД — уберёт целый класс 500-х.
3. **Контракт count (BUG-001):** сверить с реализацией Store API (Admin считает корректно —
   внутри системы есть работающий образец).
4. **Security-заголовки (BUG-009):** middleware/edge-конфиг на 6 заголовков + флаги куки —
   низкое усилие, эффект на весь продукт.
5. **SEO/a11y (BUG-010–012):** вернуть robots/sitemap-маршруты, поправить NEXT_PUBLIC_-переменные
   сборки, alt/aria в layout-компонентах.

## Ограничения достоверности (PLAN §13)

Общий sandbox (шум латентности и данные других пользователей) · посаженные баги vs
кастомизация демо · слепая зона capture платежа (мок-провайдер) · фаззинг по мини-спеке ·
замеры с одной машины. Каждый вывод отчётов этапов снабжён соответствующей оговоркой.
