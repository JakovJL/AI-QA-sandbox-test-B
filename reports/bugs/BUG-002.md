## Предусловия

Регион Europe (eur); товар Medusa Sweatshirt (`/dk/products/sweatshirt`).

## Шаги воспроизведения

1. `GET /store/products?region_id=reg_01M392A8HJPWA7MA90WZ9QSPH8&fields=*variants.calculated_price`
   → все варианты: `calculated_amount=10`, `currency_code=eur` (минорные единицы = €0,10).
2. Создать корзину `POST /store/carts`, добавить вариант: `POST /store/carts/{id}/line-items`
   → сервер считает `subtotal=10`, `item_subtotal=10` (минорные = €0,10).
3. Открыть `https://…/dk/products/sweatshirt` в браузере.

## Ожидаемый результат

Витрина отображает сумму, согласованную с расчётной ценой API/корзины: **€0,10**.
Основание: согласованность API ↔ UI; чекаут использует серверный расчёт корзины.

## Фактический результат

Витрина (SSR + после гидрации) показывает **€10.00** на карточке и в листинге `/dk/store` —
в 100 раз больше суммы, по которой реально считается корзина. Покупатель видит одну цену,
платит по другой.

## Примечания

- Гипотеза о причине: витрина трактует значение цены как целые единицы, хотя Medusa v2
  отдаёт минорные (либо обратная ошибка при заполнении демо-данных — см. §13.1 плана).
  Определение «кто прав» (данные vs рендер) — план на Этап 2: сверка прайс-листов в Admin.
- Валютный кандидат разведки («$ на /dk») не подтвердился: UI рендерит `eur`-символ €.
