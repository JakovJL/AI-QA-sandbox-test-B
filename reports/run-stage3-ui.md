## Наблюдения вне дефектов

- **blocking-fault.js** — ASCII-призрак + «good job, you found a non-functional bug! 🐛🎉» на
  каждой странице: прямое подтверждение A-002 (sandbox собран с намеренными багами).
- **Сортировки sortBy**: URL меняется, порядок нет — при равных ценах неотличимо; API-класс
  500 на order=price_* усилен в BUG-005 (`reports/observations/sortby-and-order-500.md`).
- **Инвентарь демо**: stocked=1 000 000 у всех позиций; reserved-числа согласованы с
  корзинами тестов — инвентарная логика живёт.
- **Гостевой чекаут**: единственный проходимый путь — заполнить адрес один раз и вернуться
  в чекаут из корзины (данные сохраняются между сессиями браузера).
- Аутентификация покупателя (регистрация/логин) не тестировалась в 3.x — перенесено
  (опциональный сценарий; маркированный аккаунт можно проверить в этап 4/5).
- Мобильная версия стабильнее к вёрстке, чем ожидалось: скриншоты 27.09 («$»-валюта) не
  воспроизвелись; сегодня всё в € — согласовано с ретракцией BUG-002.

## Вердикт

UI-слой демонстрирует две **высокие проблемы, блокирующие ключевой путь монетизации**:
гостевой чекаут невозможен (BUG-008 — пустая доставка на всех устройствах), а первый сабмит
адреса может выбить пользователя на 404 (BUG-007, интермиттент). Поиск недоступен (BUG-003).
При этом навигация, каталог, карточка, корзина и админка работают корректно, данные между
UI и API согласованы; мобильная вёрстка аккуратная.

Коммерческий вердикт по sandbox: **каталог и корзина функциональны, покупка через UI
завершена быть не может** — чекаут-воронка сломана на шаге Delivery.

Дальше: Этап 4 (NFR) — заголовки безопасности, rate-limit, доступность, стабильность;
ограничения достоверности — см. PLAN §13 (шум sandbox, слепая зона capture).
