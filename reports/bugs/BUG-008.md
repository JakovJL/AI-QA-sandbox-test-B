# BUG-008: На шаге Delivery список способов доставки пуст — «Continue to payment» заблокирован

| Поле | Значение |
|------|----------|
| ID | BUG-008 |
| Область | 5. Доставка / 6. Чекаут / 11. UI-состояния |
| Severity | High |
| Priority | P1 |
| Слой | UI |
| Окружение | sandbox-session-cand-c26fa443df2a4d52ba4c0f61ea385fac.fly.dev, Next.js storefront, контур А (28.09.2026) |
| Воспроизводимость | всегда (2 из 2 чекаут-сессий) |
| Статус | Confirmed (скриншот + стабильная пустота radiogroup; контраст с API — ниже) |

## Предусловия

Корзина с товаром, адрес заполнен, чекаут на шаге delivery (`/dk/checkout?step=delivery`).

## Шаги воспроизведения

1. Пройти чекаут до шага Delivery (адрес через форму или «Go to checkout» повторно).
2. Дождаться рендера блока «Shipping method» (8+ секунд, гидрация завершена).

## Ожидаемый результат

В блоке «Shipping method» отображается доступный способ (API: Standard Shipping,
`so_01M392A8QBCS2Z88KYCZEM1PSQ`, успешно применяется к корзине через API 2.3);
после выбора активируется «Continue to payment».

## Фактический результат

Блок «Shipping method» содержит только заголовок и подзаголовок; `radiogroup` **пустая**
(0 детей, стабильно по двум сессиям и после повторного ожидания). Кнопка
«Continue to payment» — `disabled`. Чекаут заблокирован: продолжить покупку невозможно.
В «In your Cart» при этом отображается Shipping €0.00.

## Артефакты

- Скриншот шага delivery: `reports/screenshots/` (контур А, 28.09)
- Контраст с API: `reports/artifacts/stage2.3-checkout-*.json` (API находит опцию и применяет)
- Детерминированная проверка: `npx tsx scripts/ts/verify-ui-journeys.ts` (проверки A, B, D —
  аналогичный источник: клиентский фетч опций на `127.0.0.1:9001` падает — вероятная причина
  пустого списка)

## Примечания

- Вероятная корневая причина общая с находкой A: клиентская ветка кода фетчит
  product-options/shipping-options с `http://127.0.0.1:9001` (localhost браузера) вместо
  бэкенда — каждый посетитель получает `ERR_CONNECTION_REFUSED`, списки не наполняются.
- Это блокер конверсии: ни один гость не может завершить покупку через UI.
- Связь с API-этапом: `GET /store/shipping-options?cart_id=…` работает (200) — дефект UI-слоя.
