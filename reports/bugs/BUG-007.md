# BUG-007: Сабмит адреса в чекауте редиректит на /null/checkout — потеря регион-префикса

| Поле | Значение |
|------|----------|
| ID | BUG-007 |
| Область | 6. Чекаут / 11. UI-состояния |
| Severity | High |
| Priority | P1 |
| Слой | UI |
| Окружение | sandbox-session-cand-c26fa443df2a4d52ba4c0f61ea385fac.fly.dev, Next.js storefront, контур А (28.09.2026) |
| Воспроизводимость | 2 из 7 известных прогонов (1 контур А + 6 контур Б); воспроизводится на мобильном вьюпорте |
| Статус | Confirmed (28.09) — **29.09: Blocked by BUG-013** (сабмит адреса не работает в новой сборке, редирект недостижим) |

## Предусловия

Гостевая корзина с 1 товаром; чекаут открыт на шаге address (`/dk/checkout?step=address`).

## Шаги воспроизведения

1. Заполнить форму адреса: First name, Last name, Address, Postal code, City, Email
   (`qa-ui-checkout@test.local`), Country = Denmark (по умолчанию).
2. Нажать «Continue to delivery».

## Ожидаемый результат

Переход на `/dk/checkout?step=delivery` с сохранённым адресом и итогами корзины.
Основание: пользовательский сценарий чекаута; регион-префикс `/dk` обязателен для витрины.

## Фактический результат

Редирект на **`/null/checkout?step=delivery`** → «Page not found», заголовок 404.
Регион-префикс заменён строкой `null` — на скриншоте страница 404 по адресу
`/null/checkout?step=delivery`.

## Артефакты

- Скриншот 404-страницы: `reports/screenshots/` (снятие контура А, 28.09)
- HTML 404 по прямому GET: `reports/artifacts/stage3-null-checkout.html` (307 при запросе через харнесс — у клиента итог 404)
- Прушот шага address с заполненной формой — в журнале контура А

## Примечания

- Гипотеза причины: при сабмите в URL подставляется значение, зависящее от переменной региона,
  которая в этот момент `null`/`undefined` (шаблон `/${regionCode}/checkout?...`). При этом
  адрес в корзину сохранился — на повторном заходе через «Go to checkout» чекаут открылся
  сразу на `?step=delivery` с корректным `/dk`-префиксом и заполненным адресом.
- **Серия контура Б (28.09, `verify-bug007-series.ts`): 0/5 прогонов с /null-редиректом** —
  все пять чисто прошли адрес→delivery (`/dk/checkout?...`). Итого 1/6 известных прогонов.
  Интермиттентность подтверждена: вероятно, гонка состояния (гидрация корзины/региона
  к моменту сабмита). Headless-прогоны стабилизируются дольше (8 c ожидания) — у живого
  пользователя шанс выше.
- Артефакт серии: `reports/artifacts/bug007-series-*.json` (5 прогонов, все URL /dk/...).
- Несмотря на низкую частоту — остаётся High severity: пользователь, попавший в редирект,
  теряет чекаут (404), данные адреса при этом сохранены; восстановление через повторный
  заход в корзину.
- **28.09 (мобильная серия, `verify-mobile-journeys.ts`): /null-редирект ВОСПРОИЗВЕДЁН
  в контуре Б** — на вьюпорте 390×844 сабмит адресной формы увёл на
  `/null/checkout?step=delivery` → 404 (проверка D1, FAIL-статус в отчёте прогона).
  Итого 2/7 прогонов. Паттерн: оба случая — первый сабмит адресной формы в новой сессии;
  после восстановления через корзину шаг delivery открывается корректно. Усиливает гипотезу
  гонки: регион-код ещё не в состоянии на момент построения URL редиректа.
- **29.09 (регрессия, `run-regression-2026-09-29.md`): серия не завершена** — в пересобранной
  витрине сабмит адресной формы не работает вовсе (BUG-013: 0 сетевых запросов, URL не меняется,
  8/8 прогонов). /null-редирект недостижим; статус «Blocked by BUG-013», повторная проверка —
  после починки/отката сборки. По §3.4 не переводить в «чисто».
