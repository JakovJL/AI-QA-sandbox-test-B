# BUG-003: Поиск витрины недоступен — /dk/search отдаёт 404, в шапке нет элемента поиска

| Воспроизводимость | всегда |
| Статус | Confirmed (контур Б: HTTP-пробы; контур А: инспекция шапки) |

## Предусловия

Нет; достаточно браузера/HTTP-клиента.

## Шаги воспроизведения

1. Открыть `https://…/dk/search?q=shirt` → HTTP 404, рендер «Page not found».
2. Открыть `https://…/dk/search?q=medusa` → HTTP 404, тот же рендер.
3. Открыть `https://…/dk/search?q=` (пустой запрос) → HTTP 404.
4. В контуре А (живая инспекция 28.09): в шапке главной и `/dk/store` отсутствуют
   иконка/ссылка/инпут поиска — только «Menu», логотип, «Cart (0)».

## Ожидаемый результат

Страница поиска рендерит результаты по валидному `q` (и корректное пустое состояние для
невалидного/пустого), а шапка starter-витрины предоставляет вход в поиск.
Основание: функциональность search-страницы в эталонном Next.js starter Medusa.

## Фактический результат

404 на любые `q` с одинаковым рендером; вход в поиск из UI отсутствует —
функционально поиск недостижим для пользователя.

## Артефакты

- HTML-дампы: `reports/artifacts/search-q-shirt.html`, `search-q-medusa.html`, `search-q-empty.html`
- сводка прогона: `reports/artifacts/verify-candidates-*.json` (3× FAIL)
- инспекция шапки: контур А, 28.09.2026 (snapshot главной и /dk/store)

## Примечания

- Либо поиск не собран в этой сборке storefront, либо маршрут сломан — требует исходников
  витрины для точной локализации (вне HTTP-поверхности).
- Скриншоты разведки 27.09 (docs/screenshots/storefront/) фиксировали тот же 404.
